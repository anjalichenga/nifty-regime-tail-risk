# Leakage Prevention Protocol & Verification Matrix (LEAKAGE.md)

This document formalizes the 17 distinct leakage risks identified in quantitative risk modeling, their explicit architectural mitigations in this codebase, and the dedicated verification tests enforcing them.

| # | Leakage Risk Vector | Architectural Mitigation in Code | Test / Automated Assertion |
|---|---|---|---|
| 1 | **Full-sample scaling / normalization** | `StandardScaler` is initialized and fit strictly on training window indices `data.iloc[:train_end]`, then used to transform out-of-sample steps forward until next refit. | `tests/test_leakage.py::test_scaler_no_future_leakage` |
| 2 | **Full-sample percentiles / ECDFs** | Empirical Cumulative Distribution Functions (ECDFs) for volatility, drawdown, and anomaly scores are computed strictly on the training set and applied forward. Observations beyond historical extremes clip to 1.0 with an `exceeds_historical_range` flag. | `tests/test_leakage.py::test_ecdf_fit_on_train_only` |
| 3 | **Centered rolling windows, backward shifts, bfill, interpolation** | Strict forbidden syntax rule: all rolling aggregations enforce `center=False`, positive shifts `shift(k > 0)`. Never use `bfill()` or `.interpolate()`. | Static AST & regex lint test `tests/test_leakage.py::test_static_lint_forbidden_patterns` grepping `src/features/` |
| 4 | **Future returns / volatility in feature engineering** | All feature calculations use causal trailing windows (`min_periods=n`). | Truncation invariance test `tests/test_features.py::test_features_truncation_invariance` verifying $X_{1..T}(T) \equiv X_{1..T_{\text{full}}}(T)$ |
| 5 | **HMM full-sample training or smoothed/Viterbi states in signals** | Causal pipeline employs ONLY pure forward filtering recursion $\alpha_t(k) = P(S_t=k \mid x_{1..t})$ implemented in `src/regimes/filtering.py`. Smoothed probabilities (`predict_proba`) and Viterbi paths (`predict`) are forbidden in causal signals. | `tests/test_regimes.py::test_forward_filter_no_future_dependence` |
| 6 | **HMM label switching resolved with full-sample statistics** | Regime indices are re-ordered after each refit strictly by the ascending state-mean of $\ln(\text{RV}_{20})$ computed on the *training window*. Names (Calm, Elevated, Stress) are strictly assigned by this training rank. | `tests/test_regimes.py::test_label_sorting_stability` |
| 7 | **GARCH parameters fit on full sample or refit daily with lookahead** | Model parameters are estimated on the training window at 63-day intervals. Intervening daily steps evaluate conditional variance using frozen parameters via `arch.univariate.base.ARCHModelResult.fix(params)`. | `tests/test_models.py::test_garch_frozen_filtering` |
| 8 | **ARIMA order $p, d, q$ selected on full sample** | Box-Jenkins identification and BIC minimization occur strictly inside the training window at 252-day intervals. Order selection never observes post-training returns. | `tests/test_models.py::test_arima_train_window_selection` |
| 9 | **EVT threshold / tail quantiles from full sample** | Threshold $u$ is chosen as the 90th percentile of standardized negative residuals within the training window; GPD parameters $\xi, \beta$ are fitted via MLE on training exceedances only. | `tests/test_risk.py::test_evt_fit_train_only` |
| 10 | **Isolation Forest fit on future data** | `IsolationForest` is fit strictly on the scaled training window at each 63-day refit. Scoring of out-of-sample days uses the frozen forest. | `tests/test_anomaly.py::test_isolation_forest_causal` |
| 11 | **Simultaneous cross-asset alignment (S&P 500, Gold, FX)** | Non-Indian series apply explicit availability lags (S&P 500: lag 1, USD/INR: lag 1, Gold: lag 1) before alignment to the NIFTY calendar, preventing same-calendar-date lookahead. | `tests/test_data.py::test_availability_lag_alignment` |
| 12 | **Drawdown event labels leaking into features or W-LOGIT** | Event labels $y_t$ (minimum forward $h$-day return $\le -x$) are used strictly for post-hoc evaluation. For W-LOGIT weighting, an $h$-day purge and embargo gap is enforced between training labels and the out-of-sample evaluation period. | `tests/test_backtest.py::test_labels_purge_and_embargo` |
| 13 | **Hyperparameter & threshold tuning on test period (2015+)** | All hyperparameters ($K=3$, GARCH Student-$t$, EVT $q_u=0.90$, CUSUM $k=0.5, h=5$, alarm threshold 50) were chosen on the Development period (2007–2014) and frozen. Config SHA256 is recorded in `outputs/run_manifest.json`. | Config hash immutability test `tests/test_leakage.py::test_frozen_config_hash` |
| 14 | **Retrospective change points used in signals** | PELT retrospective change-point analysis is restricted exclusively to descriptive in-sample reporting. Online change detection uses causal Page-CUSUM alarms. | `tests/test_changepoints.py::test_cusum_is_strictly_online` |
| 15 | **Data cleaning with future information (outlier trimming, interpolation)** | Extreme shocks (e.g. 2020-03-23 -13% move) are never trimmed or winsorized. Forward-filling is capped at 3 days (`limit=3`) and never backfilled. | `tests/test_data.py::test_no_winsorization_and_forward_fill_bounds` |
| 16 | **Dropna shifting cross-asset calendar alignment** | Master calendar is strictly defined by NIFTY trading days. Missing cross-asset observations remain NaN; features using missing series degrade gracefully without row deletion. | `tests/test_data.py::test_master_calendar_alignment` |
| 17 | **Researcher peeking (test-set overfitting)** | Single-pass evaluation on test set (2015-present). Any subsequent bug fixes are recorded as transparent amendments in `docs/DECISIONS.md`. | Verified by protocol documentation and test suite execution. |
